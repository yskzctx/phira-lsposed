feat: Phira judgment protection now actually saves and rewrites (not autoplay)

Phira's 判定保护 had two independent defects that together made it do nothing:

1. ControlsConfig.parse() rejected any mode above 2 with "未知游玩模式", and the panel's
   判定保护 button was mode 3. So selecting protection threw on save and the setting was never
   stored at all - nothing reached the native layer.

2. Mode 3 also sets requested=true, which makes lab_frame_begin() call lab_input_apply() and
   inject synthetic touches - the autoplay-with-a-rescue design the user rejected in Phigros.

Changes:

  * ControlsConfig.parse accepts modes 0-4.
  * New mode 4 (rewrite only): it does not count as "requested", so no synthetic input is
    injected, but protection_rescue() still runs and commit_original() commits the promoted
    judgment. Mode 4 keeps the assist kind and never blocks touch.
  * The panel's 判定保护 button is now mode 4.

Phira's panel and native guard numbering already agree (1=score, 2=FC, 3=AP), so no
translation is needed.
